# Security Audit — nostr-skills-registry — 2026-10-20

## Summary
Tiny JS tool (register.js ~1.2 KB, discover.js) that publishes/discovers AI-skill announcements as NIP-89 kind:31990 events via NDK against public relays. No secrets. Findings: 0C / 0H / 0M / 3L.

## Findings
| ID | Severity | File/Area | Issue | Recommended fix |
|----|----------|-----------|-------|-----------------|
| L1 | LOW | register.js | `ndk.event(...).publish()` is called without configuring an NDK signer — publishing will fail or sign with an unintended identity depending on ambient setup. | Explicitly construct `NDKPrivateKeySigner` from env (never hardcode) and pass to NDK. |
| L2 | LOW | register.js / discover.js | Events are published with a self-asserted `['verified','wot']` tag, and `discover()` returns entries without verifying any attestation — anyone can spoof the same tag. Consumers must not treat `verified` as meaningful. | Verify WoT attestations cryptographically or drop/rename the tag. |
| L3 | LOW | repo-wide | No package.json (imports @nostr-dev-kit/ndk with no pinned version), no SECURITY.md, no .gitignore. | Add package.json with pinned deps; add SECURITY.md. |

## Secrets Check
register.js and discover.js read in full; only public relay URLs (wss://relay.damus.io, nos.lol, relay.primal.net) — not secrets. Org-wide searches for `nsec1`, `sk-`, `xai-`, `nostr+walletconnect://`, `PRIVATE KEY` — **no secrets found**.

## Dependency Notes
@nostr-dev-kit/ndk imported unpinned/no lockfile (no manifest at all).

- [ ] Add explicit signer-from-env wiring.
- [ ] Add package.json + .gitignore + SECURITY.md.
